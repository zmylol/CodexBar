# CodexBar 使用指南

[← 返回项目首页](../README.md)

安装、日常操作、知识库文章约定，以及当前支持范围。

## 让进展留在视线里

同时开着几个项目时，不必挨个切回 Codex 看它进行到哪一步。CodexBar 把这件事缩成三个动作：

| 你想知道什么 | 在 CodexBar 里怎么做 |
| --- | --- |
| **谁还在跑，谁在等我？** | 看悬浮条上的状态图标。项目名常驻，详情按需出现。 |
| **刚才具体做了什么？** | 悬停打开会话预览，直接读助手正文，展开命令与工具结果。 |
| **现在需要我接手吗？** | 点击项目或“切到项目”，恢复并前置对应的 VS Code 窗口。 |

预览支持 Markdown、代码块和文字选择。长会话先展示最近 30 条内容，向上翻阅时分批显示旧消息；新回复默认跟随到末尾，回看历史时保留你的阅读位置。

悬浮条可拖动，也可放到屏幕四角；任务多时选择固定高度滚动，或让列表自动展开。应用使用 SwiftUI 与 AppKit，没有第三方 Swift Package 依赖。

## 按知识库查看今日新增文章

**点书本 → 点左侧知识库 → 在右侧查看今日文章标题和一段摘要。** 600×520 点的双栏面板使用统一系统磨砂玻璃背景，左侧保留所有一级知识库名称，并显示各库未查看的新文章数。点击某个知识库后只清除它的数字，右侧仍显示该库当天收录的文章；点击标题在 Obsidian 打开。没有新增的库仍列出，选中后右侧显示“今日暂无新增”。首页、同步日志、索引及旧文章修改不进入这份清单。

启动优先连接上次使用的总目录；没有有效记录时，从本机 Obsidian 登记信息中选择唯一有效的知识库，或唯一标记为打开的知识库。无法确定时，通过书本选择包含 `.obsidian` 的整个总目录，无需逐个添加分类。

### 自动化分批收录，文章到达就显示

从零配置目录、文章和每日任务，见[知识库与每日自动化配置攻略](KNOWLEDGE_SETUP.md)，其中包含可直接复制的示例与摘要复核提示词。

各知识库的自动化可以在一天内不同时间运行。CodexBar 持续监听已连接目录；每篇 Markdown 写入后读取文章信息，加入对应知识库当天的清单，无需等其他自动化完成，也不需要额外 Hook 或接入任务调度器。只有文章信息已经写入文件时才可识别，面板不表示抓取任务开始或完成。

文章采用现有的 frontmatter 约定：

```markdown
---
type: article
collected: '2026-09-11'
published: '2026-08-20'
---
# 文章中文标题

## 摘要

本文介绍如何为并行任务设计交接条件，并通过独立验证判断结果是否可用，减少反复切换项目的成本。
```

`collected` 是首次收录日期，支持 `YYYY-MM-DD` 或带时区的 ISO 8601 时间。按北京时间判断当天，不能用发布日期、文件名日期或最近修改时间替代。标题依次使用正文一级标题、frontmatter 的 `title`、文件名。`type` 不是 `article`、缺少有效收录日期的笔记不列为新增，因此空日期模板与管理文件不会产生提醒。

标题下方显示正文 `## 摘要` 的第一段，也识别“中文摘要”和“Summary”标题。换行合并成一段，移除链接地址及常见 Markdown 标记；没有摘要时只显示标题。摘要随文件写入或修改自动更新，补写摘要不会增加未查看篇数。内容只在本机提取，不调用在线生成服务或改写笔记。

- **分批累计：** 早上和下午收录的文章在同一天按库累计；有精确时间时按收录时间倒序，同日只有日期的文章按路径稳定排序。
- **补读范围：** 顶部可切换“今天／昨天／近七天”，默认今天。近七天包含北京时间今天及前六个日历日；切换范围保留所选知识库，不会自动标记文章已查看。
- **编辑不重复提醒：** 今日文章后续补写正文仍保留，旧文修订不进入今天；首次收录日期应保持不变。
- **独立数字提醒：** 每个知识库显示当前范围的未查看篇数，点击该库只确认当前范围内的文章，其余库和范围外的文章保持原状态。仅打开面板、切换范围或悬停不会清除数字；当前选中库再收到新文章时数字重新出现，再次点击可清除。文章列表保留。书本入口的小圆点只提示今天尚未查看的文章，补读昨天不会清除今天的提醒；应用运行期间可确认的跨库移动保留已查看状态，删除文章从阅读清单移除。
- **重启恢复：** 首次连接和重启都会从文章元数据恢复清单，不依赖应用当时是否运行。已查看记录在本机保存，按总目录隔离；重启默认回到今天，近七天内看过的文章不会重复提醒。仅保存文章标识指纹与收录时间，不保存标题、摘要或正文；总计最多保留 10,000 条近七天回执，超量优先保留本次明确查看的文章，再移除其余收录时间较早的记录。
- **每天切换：** 跨北京时间零点后，各范围随新日期推进，分类保留；昨日文章的已查看状态继续用于补读。每 30 秒轻量检查缓存日期，打开面板时也立即检查；不为日期切换轮询文件夹。

[查看知识库原生界面演示](../README.md#知识库今天收了什么一眼读明白)（使用虚构项目与文章数据）。

面板关闭后文件监测继续运行。鼠标离开立即开始半秒淡出，移回取消隐藏；选择文件夹或键盘操作期间保持显示。首次打开等待选择知识库；再次打开保留所选知识库，更换总目录后重置。面板可见期间暂停任务缩略图，避免任务悬停打断阅读。

当前连接一个总目录，默认其一级文件夹作为各知识库分类，空目录也保留。顶部“管理目录”中的勾选表示参与读取；取消勾选或右键分类选择“排除此目录”，会停止扫描该目录及其内容，同时隐藏分类和文章，原文件保留。重新勾选即可恢复读取，全部排除后也能从顶部恢复。排除设置在本机按总目录保存，更改设置不确认文章已查看。

根目录散放的 Markdown、隐藏文件及符号链接不参与。各库共用后台扫描预算：最多 10,000 篇、每篇 256 KiB；变更预览的正文缓存最多 32 MiB，超限或读取失败会提示。文章列表使用独立索引，正文缓存满后仍可发现新文章；每篇标题最多 1 KiB、摘要最多 4 KiB，较长文本显示省略号，全文仍可在 Obsidian 阅读。文章索引、标题、摘要和正文只在内存中处理，已查看回执另存于本机偏好，不新增磁盘文章索引或改写文章；无法精确区分文件写入来自 Codex、Obsidian 还是其他工具。

如果原路径下的知识库文件夹被另一个目录替换，CodexBar 会提示并重新建立基线，清除旧库的审阅记录和已读状态；不会把旧库所有笔记误报为删除。应用运行期间，可唯一确认的文章改名或移动会保留已读状态；停机期间的移动或无法唯一确认文件身份时，保守地作为新路径处理。

VS Code 的项目悬停“变更”页仍独立跟随已收到的成功文件修改记录，保留差异与回看功能；详细边界见 [知识库验证说明](KNOWLEDGE_PREVIEW_VERIFICATION.md)。

## 开始使用

构建需要 **macOS 13+、Swift 6.0+、Xcode Command Line Tools**。知识库文件回看可独立使用；任务状态和会话预览另外需要官方 **Visual Studio Code Stable** 和支持 Hooks 的 **OpenAI Codex IDE Extension**。

当前按源码构建安装。构建产物使用本机架构和 ad-hoc 签名，适合本地使用与测试，未经过 Developer ID 签名及 Apple 公证。

### 1. 构建并安装

```sh
git clone https://github.com/zmylol/CodexBar.git
cd CodexBar
scripts/install-app
# 使用 VS Code 任务功能时再安装 Hooks
scripts/install-hooks
```

应用会安装到 `~/Applications/CodexBar.app`，Hook 可执行文件安装到 `~/Library/Application Support/CodexBar/bin/codexbar-hook`。

Hook 安装器会备份并合并现有配置，保留第三方 handler。默认配置路径为 `~/.codex/hooks.json`；设置了 `CODEX_HOME` 时跟随该目录。

### 使用已公证的二进制发布包

如果维护者提供了附 SHA-256 校验和、已签名公证的发布包，解压后先将 `CodexBar.app` 放入 `/Applications` 或 `~/Applications`，再打开应用，无需 Swift、Python 或源码。确认包所列的 macOS、架构、VS Code 和 Codex 扩展版本与你的环境相符；未列出的组合不代表已验证。

使用任务功能时，从菜单“连接与设置 → 安装或更新任务连接…”打开随应用附带的安装助手。它在终端运行，合并现有 Hook 配置并保留其他工具的 Hook，然后提示你在 Codex 中审核。安装器引用已安装应用内的 helper，因此移动应用后要重新运行；从下载目录或临时运行位置启动时会拒绝写入配置。只看知识库可以跳过任务连接。

正式分发由维护者按 [RELEASING.md](RELEASING.md) 完成；源码构建或 `prepared` 候选不等于已公证的发布包。

### 2. 在 VS Code 中启用 Hooks

**只用知识库功能可跳过这一步。** 点击右上角书本，在独立面板里查看自动识别的分类；未找到总目录时，按提示选择即可。

重新加载 VS Code，在 Codex 侧栏打开 **Codex settings → Hooks**，必要时点击 **Reload hooks**。打开 **User config**，检查指向 `codexbar-hook` 的命令，再审核并点击 **Trust**。

当前安装器覆盖五种事件：`UserPromptSubmit`、`PreToolUse`、`PermissionRequest`、`PostToolUse`、`Stop`。新增或修改的 Hook 定义需要重新审核后才能运行，详见 [OpenAI 官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。

这里使用 IDE 的 Hooks 设置页；CLI 文档中的 `/hooks` 不是 IDE 聊天命令。如果看不到该设置页，先更新扩展，再按 [Hook 兼容性说明](HOOK_COMPATIBILITY.md)检查。

### 3. 启动，允许窗口切换

```sh
open "$HOME/Applications/CodexBar.app"
```

前往 **系统设置 → 隐私与安全性 → 辅助功能**，启用 **CodexBar**，用于同步、恢复和切换 VS Code 窗口。尚未授权时仍可接收和显示已知 Hook 任务，窗口相关功能需要授权后使用。

成功识别已打开的根目录或工作区后，悬浮条就会保留项目入口；尚无任务时显示“暂无任务”。在对应窗口中发起 Codex 任务后，再显示任务进展。

**更新已有安装：** 先从悬浮条菜单退出 CodexBar，再运行安装命令。Hook 定义变化后重新审核并加载；重新构建的 ad-hoc 应用也可能需要重新添加辅助功能授权。

## 连接状态与排查

打开悬浮条三点菜单中的“连接与设置”，查看当前连接与待处理事件。连接指南也可从这里打开。

| 状态 | 下一步 |
| --- | --- |
| 需要辅助功能授权 | 点击“辅助功能设置”，允许 CodexBar，然后返回 VS Code |
| 未打开 VS Code 窗口 / 等待任务 | 打开官方 VS Code Stable，在项目中向 Codex 提交任务 |
| 正在连接 / 正在重新连接 | 等待有限次数的自动恢复；不会持续无限重试 |
| 已连接 Codex | 本地连接已建立；Hooks 是否审核通过，仍需在 Codex 设置中确认 |
| 连接暂不可用 | 确认 VS Code 和 Codex 扩展已运行，点击“刷新连接与任务” |
| Codex 扩展暂不兼容 | 查看维护者记录的兼容版本组合；升级适配后再刷新，已有 Hook 状态仍可作为保底 |

连接断开后，会依次等待 0.25、0.5、1、2、4 秒尝试重连；停止应用或关闭全部跟随任务会取消重试。手动刷新会开启新一轮恢复。真实兼容版本应以发布包随附记录为准，不能把自动测试通过当作所有扩展版本兼容。

应用关闭期间 Hooks 仍可能产生事件。可靠 Inbox 的正常保留预算为 2,048 条、32 MiB，写入到达超过 7 天的旧事件会在后续写入或读取时清理。超出容量时优先保留较新的事件；历史进展可能不完整。发生裁剪时应用会提示并核对当前打开的任务，菜单显示待处理数量与累计裁剪计数。计数在中断清理后可能保守多报，不表示精确丢失了多少轮任务。多个进程争用维护锁时会先接收新事件、推迟裁剪，预算可短暂超出；同步 Hook 不会无限等待维护锁。

## 日常操作

| 操作 | 效果 |
| --- | --- |
| 悬停或键盘聚焦有任务的项目 | 打开会话预览 |
| 右方向键 / 菜单“查看任务详情” | 把焦点移入预览，方便滚动和选择文字 |
| 展开用户消息或工具条目 | 阅读收到的正文、命令与输出 |
| 向上翻阅 / “显示较早内容” | 分批显示已接收的旧消息；需要补读时可点“加载较早内容” |
| “回到最新” | 回到末尾并恢复自动跟随 |
| 预览内方向键、Page Up / Down、Home / End | 滚动正文 |
| Esc | 关闭预览；键盘进入时把焦点还给悬浮条 |
| 点击项目 / 预览底部“切到项目” | 恢复并前置对应的现有 VS Code 窗口，保留其他窗口的最小化状态 |
| 项目三点菜单或右键菜单“专注此项目（最小化其他窗口）” | 恢复并前置对应窗口，同时最小化其他标准 VS Code 窗口 |
| 顶部书本 / 空态“打开知识库” | 打开知识库列表，保留各库未查看提醒 |
| 知识库分类 / 文章标题 | 点击知识库清除该库数字并在右侧列文章；点击文章在 Obsidian 打开 |
| 顶部菜单“刷新 VS Code 任务” | 重新扫描已打开窗口中的 Codex 任务 |
| 顶部菜单 | 切换显示模式、移动悬浮条、清理任务或退出 |

窗口切换要求项目与窗口**唯一匹配**，并保留目标窗口原本打开的页面；需要定位具体 Codex 对话时，在该窗口中继续选择。

**暂无任务的项目：** 灰色空心圆和“暂无任务”表示该窗口已识别，但没有可显示的 Codex 任务。仍可点击回到现有窗口；不显示执行或完成状态，也不打开会话预览。这不表示该窗口的 Codex 扩展已连接。

**并行开发 Git worktree：** 同仓库的工作目录连续显示，仓库名只出现一次，下方各行显示分支短名，关联工作树带有 `WT` 标记。Git 创建记录能够确认来源且来源分支的窗口也打开时，子分支会缩进并用树线连接；只有同仓库关系时保持平级。父窗口关闭后只保留实际打开的分支，并显示“创建自”来源，不增加虚拟任务。创建来源表示历史记录，不代表分支当前的提交祖先。长分支名优先保留能区分其他工作目录的部分；有任务时可打开预览查看完整分支、来源和路径，暂无任务时可查看悬停提示。切换分支后自动更新，也可手动刷新；每个工作目录保留独立状态和窗口入口。同仓库整组按最高优先级任务的位置排序。其他项目和多项目工作区继续显示实际打开的根目录或工作区名称。

支持从子分支继续创建工作树，最多向下缩进三级，更深的来源以文字说明。创建时省略起点可能只留下 `Created from HEAD`；这类记录、提交号来源或过期记录不会被猜测为某个父分支。需要保留可识别的来源时，在 `git worktree add -b <新分支> <新目录> <来源分支>` 中明确填写本地来源分支名。

## 支持范围

| 环境 | 当前支持情况 |
| --- | --- |
| macOS + 官方 VS Code Stable + Codex IDE Extension | 支持本地任务；窗口操作要求辅助功能权限 |
| Codex 桌面端、终端 Codex CLI | 可使用独立知识库文件回看；未接入其任务状态或会话正文，Hook 事件仍被来源校验过滤 |
| Cursor、Windsurf、VS Code Insiders | 暂不支持 |
| Windows、Linux、远程任务 | 暂不支持 |
| 已保存的本地 `.code-workspace` 或 VS Code 本地未命名工作区 | 整个工作区显示一条，以工作区命名，点击回到该窗口 |
| 同一文件夹在单独窗口和多项目工作区内同时打开 | 各保留对应根目录或工作区入口，点击按所选入口切换 |
| 同名工作区、同一工作区重复窗口或自定义窗口标题 | 不保证唯一匹配；有歧义时拒绝切换 |

列表按能确认身份的已打开根目录或工作区显示入口，不要求先有 Codex 会话；在子目录运行的会话也归到打开的根目录。欢迎页和无法确认根目录的窗口不会被当作项目。首次尚未获得窗口列表时，不会把历史任务显示为已打开项目。成功同步后关闭窗口会隐藏对应条目；临时读取失败会保留最后一次成功同步的结果。

如果使用“将文件夹添加到工作区”，CodexBar 会读取 VS Code 记录的打开工作区及其中的 `folders`，将成员会话合并为一条工作区入口。例如 `Example-Workspace` 包含 `project-alpha` 等项目时，列表显示 `Example-Workspace`；未保存时显示“未命名工作区”。行内按现有任务优先级展示一个会话，预览注明该会话所属项目，其余会话继续同步；“删除当前任务”只删除当前展示的会话。工作区关闭后条目隐藏，已有记录保留。

删除当前任务后，若没有其他可展示的会话，仍打开的项目会显示“暂无任务”。刷新不会恢复已删除的那一轮任务；收到真正的新一轮任务后，才重新显示该会话的进展。

会话预览依赖 Codex 扩展的内部本地接口，兼容性会随扩展版本变化。已验证的版本组合、真实传输结果与验证边界见 [会话预览验证报告](CONTENT_PREVIEW_VERIFICATION.md)。

## 状态和正文从哪里来

| 状态 | 含义 |
| --- | --- |
| 灰色空心圆 · 暂无任务 | 已识别打开的项目，尚无可显示的 Codex 任务；可点击回到窗口 |
| 🔵 执行中 | 当前任务正在进行 |
| 🔺 需要处理 | 会话等待审批或用户输入 |
| ✅ 可查看 | 当前一轮已停止，可以回看结果；不代表任务一定成功 |

**Hooks 接收任务事件。** 提交、审批请求和停止事件形成三种基本状态；工具开始与完成事件补充活动摘要和审批关联。应用未运行时，生命周期事件仍可进入本地队列。

**本地连接同步当前进展。** CodexBar 跟随可见任务的已知会话，从原 VS Code 会话的 IPC 状态更新等待、恢复执行和停止，也为展开的预览读取消息与工具结果。状态、窗口和队列更新由事件驱动，不再每五秒查询 App Server。

**历史恢复补充已打开项目的任务。** 启动、手动刷新或窗口变化时，通过官方扩展内置的 Codex App Server 查询 VS Code 线程元数据，只恢复能与现有窗口唯一匹配的任务。项目入口不依赖恢复到旧任务。实时接口不可用时保留 Hook 路径；能匹配的工具完成事件可恢复执行状态，无法确认的审批保持保守状态。

实现细节见 [架构说明](ARCHITECTURE.md)。

## 内容留在本机

CodexBar 本身没有遥测、账号系统或主动上传数据的网络客户端。

- **任务记录保持精简：** 保存必要的会话标识、项目路径、状态和脱敏后的 prompt 首行摘要；Hook 不归档完整对话。
- **预览正文只放在内存：** 只为当前展开的一个会话保留预览状态，关闭、切换或退出后释放，不写入任务文件或日志。
- **知识库回看留在本机：** 自动识别或手动选择的总目录会在后台读取 Markdown，基线、差异、文章标题和收录日期只留在内存；本地偏好保存总目录路径。VS Code 悬停模式另保存回看版本的 SHA-256 指纹，均不保存笔记正文。
- **原文按原样展示：** 预览不经过 Hook 摘要的脱敏规则，可能包含会话中的敏感信息。

官方 Codex 组件及服务的数据处理遵循其自身规则。数据字段、保留期限和删除方式见 [隐私说明](../PRIVACY.md)。

## 常见问题与边界

**项目没有显示，或一直显示“暂无任务”？**

项目入口缺失时，先检查应用是否运行、官方 VS Code Stable 是否打开了文件夹或工作区，以及 CodexBar 是否有辅助功能权限，再从顶部菜单刷新窗口。欢迎页和无法确认根目录的窗口不会生成入口。入口显示“暂无任务”时，检查 Codex 扩展是否运行、更新后的 Hooks 是否已审核并重新加载，再在该窗口发起任务。只用 Codex 桌面端时没有任务进展也正常，知识库从右上角书本打开。需要验证扩展是否真的派发事件时，再使用可选的 `scripts/install-hooks --probe`，按 [Hook 兼容性测试](HOOK_COMPATIBILITY.md)执行；Probe 不写入正式任务列表，验证后需要切回正式 Hooks 并重新审核。

**预览里缺少内容？**

助手正文和已收到的工具结果可以直接阅读；运行中工具输出可能在完成或刷新后补齐。较早历史需要按需加载，图片和未支持的附件请回原会话查看。预览设有 32 MiB 内容预算及结构上限，超限会提示无法读取；不承诺任意规模的全部内容实时镜像。断线时可保留本次已接收的内容，并提示重试。

**为什么没有恢复某个旧任务？**

历史恢复依赖现有窗口的项目匹配；同名或多窗口场景会保守处理。一次扫描超过 500 条未归档 VS Code 线程时会放弃该次恢复。这是历史恢复的保护上限，与预览消息条数无关。

**如何模拟三种状态？**

将路径换成已经在独立 VS Code 窗口中打开的真实项目路径：

```sh
scripts/send-test-event running /path/to/project-alpha "检查登录流程"
scripts/send-test-event attention /path/to/project-alpha
scripts/send-test-event ready /path/to/project-alpha
```

模拟事件用于验证本地处理链路；真实扩展派发和窗口操作仍需按 [人工验收清单](MANUAL_TEST.md)检查。

## 开发与贡献

这是一个通过 **Vibe Coding** 做出来的小工具，起点很简单：同时让 Codex 处理几个项目时，想少切几次窗口。欢迎带着使用体验、问题复现或 PR 一起把它打磨得更顺手。

| 命令 | 用途 |
| --- | --- |
| `scripts/test` | 完整测试：Swift 核心、Hook、模拟端到端、release bundle 与隔离安装 / 卸载 |
| `scripts/test-preview-performance` | 独立的预览状态、原生滚动和性能检查，需要已登录的 macOS 图形会话 |
| `scripts/test-knowledge-autohide` | 多知识库不增加 Bar 高度、独立面板复用、离开立即半秒淡出及文件选择器暂停检查，需要已有 debug 构建和 macOS 图形会话 |
| `scripts/build-app` | 只构建本机架构的应用 bundle |
| `scripts/install-app` | 构建并安装应用与 Hook 可执行文件 |

核心测试使用兼容独立 Xcode Command Line Tools 的 `codexbar-tests` 可执行目标，请使用 `scripts/test`，不要用 `swift test` 代替。

## 卸载

```sh
# 卸载应用和 CodexBar 管理的 Hooks，保留本地数据
scripts/uninstall-app

# 同时删除任务、事件及备份（不可恢复）
scripts/uninstall-app --purge-data
```

以上两种方式按需选择。只移除 Hooks 可运行 `scripts/uninstall-hooks`；窗口偏好、系统授权和完整配置恢复方式见 [隐私说明](../PRIVACY.md#删除数据)。
